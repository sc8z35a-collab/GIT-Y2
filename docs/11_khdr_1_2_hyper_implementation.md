## 1. 何が変わったか（ひと目で）

| 項目 | KHDR 1.1 | **KHDR 1.2 hyper（実装済み）** |
| :--- | :--- | :--- |
| シーンの光 | 画家的な値（太陽 2.32、空 1.08、空ドームは手描きのグラデーション） | **物理大気から計算**した太陽照度・色、天空照度、空の輝度、霧の色（lux / cd/m²） |
| 露出 | GPU 1×1 の単段順応（可動域 1.63 EV） | **GPU ヒストグラム → CPU の二段順応**（短期 ±2.0 EV ＋ 長期 0.03〜900 cd/m²、明順応の上限 約 3,600 cd/m²）→ **事前露出** |
| 局所トーンマップ | 5 タップのバイラテラル（局所コントラスト強調） | **gather 型バイラテラルグリッド**による局所露出（ベース / ディテール分解、範囲フィット） |
| グレア（ブルーム） | 閾値 1.02、タップごとの Karis、エネルギー非保存 | **表示できない余剰光だけ**を、**CIE 2002 眼球散乱関数**の形で拡散（13 タップ、グループ Karis） |
| AO / 接地影 | 全放射輝度に乗算 | **K-SplitLight**: AO は環境光だけ、接地影は直射光だけ |
| トーンマップ | K-Filmic v2（RGB 色相だけ一定） | **K-Filmic v3**: GT 曲線 × Oklab 定色相 × 色域境界 LUT |
| 色域 | sRGB | **Display-P3**（対応画面で自動） |
| 暗所視 | 露出後輝度で判定 | **順応輝度**で駆動（Larson の暗所視輝度） |
| ディザ | 静的な sin ハッシュ | 時間方向の IGN 三角ディザ |
| 故障時 | — | シェーダー失敗を検出して **1.1 へ自動退避** |

## 3. POCO F7 向けの最適化

1. **静的な太陽の LUT を一度だけ作る**: 大気の 3 つの LUT は起動時のみ生成し、毎フレームのコストは空と各画素での 1〜2 回の参照だけです。
2. **キャンバスの MSAA を省く**: KHDR では自前の MSAA HDR ターゲットに描くので、キャンバス側の MSAA バックバッファとその解決を作りません。途中で KHDR OFF に切り替えた場合は、キャンバスと同じ描画規則（トーンマップと sRGB 変換をシェーダー内で行い、表示空間で MSAA を解決）の RGBA8 MSAA ターゲットに描いてから画素をコピーするので、OFF の見た目もアンチエイリアスも変わりません。
3. **タイル型 GPU の作法**: すべての全画面パスを三角形 1 枚にし、描画前にクリアします（Adreno のタイルメモリへの前内容ロードを避けるため）。
4. **mediump のピラミッド**: 縮小・拡大の 10 パスは FP16 演算で、UV だけ highp にしました（1280 px 超の画面で 0.6 テクセルずれる典型的な不具合を防ぐ）。入力は 8000 で上限を切り、FP16 のオーバーフローを避けます。
5. **gather だけで統計を作る**: ヒストグラムとグリッドはスキャッタ、アトミック演算、float ブレンドを使わない小さなパスで、拡張機能の差に左右されません。
   - **ヒストグラムの並列化**: 出力を 65 × 1 から 65 × 16 にし、各行が画面の横帯 1 本だけを集計します（部分ヒストグラムの合算は CPU で 1,040 回の加算）。65 画素だけでは Adreno の 1〜2 ウェーブが 1 つのシェーダーコアで全画素を順に読むことになり、メモリ待ちが隠れません（ネイティブ解像度で約 3 ms の見積もり）。並列化で、ループの長さは 1/16、並列度は 16 倍になります。
   - **読み戻し中は作らない**: 前回の読み戻しが終わるまでヒストグラムのパスを省きます（結果を誰も読まないため）。GPU が詰まって読み戻しが 2〜3 フレーム遅れるときほど、このパスの実行回数は自動的に 1/2〜1/3 に減ります。
6. **読み戻しで止めない**: ヒストグラムと大気の要約は PBO + fence の非同期読み戻しで受け取ります。露出は CPU 側で事前露出として光源に掛けるので、GPU が露出を参照するパスは不要です。
7. **事前露出による FP16 の安全化**: 浜辺（約 8,000 cd/m²）でも坑内の深部（約 0.02 cd/m²）でも、バッファの値は中間灰付近に収まります。
8. **失敗時の安全装置**: シェーダーのコンパイル失敗、または `EXT_color_buffer_float` の不在を検出すると、自動で KHDR 1.1 に切り替えます。

## 4. 検証

### 4.1 自動チェック
- `npm run build`（`tsc --noEmit` と `vite build`）が通ること。
- ヘッドレス Chromium（SwiftShader WebGL2）で 8 視点（浜辺・村・山頂・カルデラ・H01 和室 2 方向・炭鉱坑道・坑口）を描画し、シェーダーエラーとページエラーが 0 件であること。収集には [`scripts/khdr_lab_capture.cjs`](../scripts/khdr_lab_capture.cjs)、比較には [`docs/research/khdr_1_2/lab_compare.py`](research/khdr_1_2/lab_compare.py) を使います。
- モード切り替え（hyper → OFF → 1.1 → hyper）のたびに、レンダラーの状態（トーンマップの種類）とエラーを確かめること。OFF の画像は、最初から OFF で起動した画像とも比べます（[`scripts/khdr_mode_switch_check.cjs`](../scripts/khdr_mode_switch_check.cjs)）。

### 4.2 結果
**ビルド**: `npm run build`（`tsc --noEmit` と `vite build`）が通りました。バンドルは 1,098 kB（gzip 296 kB）で、1.1 のみの版（`main` の 1,036 kB）から 62 kB（約 6%）増えました。

**ヘッドレス Chromium（SwiftShader WebGL2、HD 1280×591、Shadow Flame Flash、各視点 10 フレーム）**: シェーダーエラーとページエラーはいずれも **0 件**でした。非同期ヒストグラムの読み戻しは毎フレーム届き、K-Adapt v2 も動作しました。

**モード切り替え**（[`khdr_mode_switch_check.cjs`](../scripts/khdr_mode_switch_check.cjs)）: hyper → OFF → 1.1 → hyper の各段階で、レンダラーのトーンマップ（hyper と 1.1 は None、OFF は ACES 1.06）とシェーダーエラー 0 件を確認しました。途中で切り替えた OFF の画像は、最初から OFF で起動した画像と空と海で一致しました（平均差 0.00 / 0.04 コード値）。地面の差（平均 4.3）は雲の影が動いた分です。輪郭は MSAA で滑らかなままです。

**KHDR 1.1 の回帰チェック**: このブランチの KHDR 1.1 を、`main` の KHDR 1.1 と同じ視点で比べました。坑道（mine_drift）は全画素が一致し、和室（h01_to_door）は 99.6% の画素が一致しました。浜辺も統計は同じです（平均輝度 0.205 / 0.207、白飛び・黒潰れ 0%）。差は波と雲の動きによるものです。K-SplitLight はアルファだけを書き換え、1.1 はシーンの RGB しか読まないため、1.1 の見た目は変わりません。

## 5. まだ実装していないもの（次の段階）

| 項目 | 理由・次の手 |
| :--- | :--- |
| **K-Temporal（TAAU）**と**K-Governor** | 風で揺れる葉のゴースト対策（解析的な速度ベクトルの MRT 出力）まで含めて実機で詰める必要があるため、次の段階で行います。現状のアンチエイリアスは MSAA 2×（モバイル）/ 4×（PC）です。 |
| **屋内の天空遮蔽（K-SkyVis）** | 半球光は屋根や壁で遮られないので、屋内が「屋外の日陰」程度に明るく見えます。上空からの深度マップで天空の見え具合を求める方式を計画しています。 |
| 地形テクスチャの `DataArrayTexture` 化、IBL | サンプラー枠（16）を空けて、空を映す鏡面反射を入れる準備です。 |
| 本物の HDR 出力（1.3） | WebGL の `drawingBufferToneMapping` の出荷を待つか、WebGPU に移行します。K-Filmic v3 は peak を引数に持つので、出力側の対応だけで済みます。 |

## 6. 使い方

- **設定画面**: 「KHDR 1.2 hyper / KHDR 1.1 / KHDR OFF」を切り替えられます。HUD には現在の順応 EV（EV100）を表示します。
- **URL**: `?khdr=hyper|1.1|0`、`?gamut=srgb|p3`。
- **デバッグ API**（ブラウザのコンソール）: `__KUROISO_DEBUG__.getKhdr()` で順応・事前露出・大気の値を取得し、`__KUROISO_DEBUG__.setKhdrDebugView(true)` で EV ゾーンを疑似カラー表示します。
